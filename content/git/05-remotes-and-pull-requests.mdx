## Everyone has a full copy

Git is **distributed**: every person has the entire project and its entire history on their own computer. To share work, teams agree on one shared copy, called a **remote**. Most often it lives on **GitHub**, though GitLab, Bitbucket and Azure DevOps do the same job.

```text
            ┌────────────────────┐
            │  remote (GitHub)   │
            └────────────────────┘
          push ↑   ↓ pull   push ↑   ↓ pull
     ┌──────────────┐        ┌──────────────┐
     │  your laptop │        │  teammate's  │
     └──────────────┘        └──────────────┘
```

| Command | What it does |
| --- | --- |
| `git clone url` | Make a new local copy of a remote repository. You do this once, to join. |
| `git push` | Send your new commits up to the remote. |
| `git pull` | Get others' new commits and merge them into your copy. |
| `git remote -v` | List the remotes this copy knows about. |

The remote you cloned from is called **`origin`** by convention.

If your push is rejected because the remote has commits you don't have, **pull first**, sort out any conflicts, then push. Never "force push" over a shared branch unless you're certain, because it throws away other people's work.

## Pull requests

On a team, people don't usually push straight to main. Instead:

1. Make a **branch** for the change.
2. Commit, and **push the branch** to GitHub.
3. Open a **pull request** (PR): "please merge my branch into main", with a description of what and why.
4. Teammates **review** it: they read the changes, comment, and ask questions.
5. **Automated checks** run, such as tests.
6. Once approved, it's **merged**, and the branch is deleted.

Pull requests catch mistakes before they reach main, spread knowledge across the team, and leave a record of why each change was made.

### Good pull requests

- **Small and focused** on one thing.
- **A clear title and description**: what changed, why, and how to check it.
- **No surprises**: no unrelated reformatting, and certainly no secrets.

### Forks

To contribute to a project you can't push to, like an open-source project, you **fork** it, making your own copy on GitHub, push to your fork, and open a pull request from there.
