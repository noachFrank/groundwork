## When Git can't decide

Most of the time, Git merges branches by itself, even when both changed the same file, as long as they changed **different lines**. But when both changed the **same lines** differently, Git can't know which is right. So it stops and asks.

That's a **merge conflict**. It isn't an error, and nothing is lost. It's Git being careful.

## What a conflict looks like

Git writes both versions into the file between markers:

```text
<<<<<<< HEAD
<h1>My homepage</h1>
=======
<h1>Welcome to my site</h1>
>>>>>>> new-title
<p>Made by me.</p>
```

- Between `<<<<<<< HEAD` and `=======` is the version on **your current branch**.
- Between `=======` and `>>>>>>> new-title` is the version from the **branch being merged in**.
- Everything outside the markers merged fine.

## Resolving it

1. **Open the file** and find the markers. Editors like VS Code highlight them and add buttons such as "Accept current" and "Accept incoming".
2. **Decide what it should say.** Keep one side, the other, or a mix of both. It's a judgment, so if it's someone else's code, ask them.
3. **Delete every marker line.**
4. **Stage and commit:** `git add file`, then `git commit`.

Changed your mind halfway? `git merge --abort` puts everything back as it was before the merge.

<Callout kind="warn" title="Check for leftover markers">
Git won't stop you committing a file that still has `<<<<<<<` in it. Those lines then break the code or appear on the website. Always look over the file before you commit.
</Callout>

## Fewer conflicts

- **Merge often.** The longer branches stay apart, the more they drift and the bigger the conflicts.
- **Keep branches small.** One feature or fix per branch.
- **Talk.** If two people need to rework the same file, a quick message saves a painful merge.

<ConsultantNote>
A team that dreads merging usually has branches that live for weeks. Suggesting smaller, shorter-lived branches and frequent merges is simple advice that makes a big difference to how quickly a client's team can ship.
</ConsultantNote>
