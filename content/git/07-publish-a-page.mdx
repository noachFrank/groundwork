## Stage 1's milestone

This is where it comes together: the terminal, Git, asking AI good questions and checking what it gives you. By the end, you'll have a real page on the public internet, with an address you can send to anyone.

## How it fits together

```text
your laptop                GitHub                       the world
my-site/index.html  ──push──▶  my-first-site repo  ──Pages──▶  https://you.github.io/my-first-site/
```

1. **Git** tracks your page's versions on your laptop.
2. **Pushing** copies those commits to a repository on **GitHub**.
3. **GitHub Pages** serves the files in that repository as a website.

Every time you push a change, Pages republishes the site, usually within a minute or two. That's a **deployment**, and plenty of professional hosting works exactly the same way.

## Using AI for this, the right way

It's fine, and realistic, to have AI help write the page. But it's *your* page:

- **Read the code** before you publish it, and ask about anything you don't understand.
- **Change something yourself**, like the colors, a heading or a section.
- **Check what's in it.** AI sometimes adds links to outside scripts or images you didn't ask for. For this page, it should be one HTML file with no outside links.

## Signing in from Git

GitHub doesn't accept your account password from the terminal. Git for Windows includes **Git Credential Manager**, which opens a browser window to sign in securely the first time you push. After that, it remembers.

## Static sites

Your page is a **static site**: files that are sent to the browser exactly as they are. There's no server code and no database. Static sites are cheap or free to host, very fast, and hard to hack, because there's very little to attack. Many real business websites are static.

When a site needs logins, a database or payments, it needs a server too. That's Stage 3.

<ConsultantNote>
"Do we really need a server for this?" is a question that saves clients money. Many small business sites would be faster, safer and nearly free as static sites. Recognizing when the simple option is enough is good consulting.
</ConsultantNote>
