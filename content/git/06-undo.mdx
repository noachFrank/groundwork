## Almost everything in Git can be undone

That's one of the best things about it. The trick is picking the right undo for the situation, and the most important question is: **has anyone else got this commit yet?**

## Which undo?

| The mistake | The fix | Safe after pushing? |
| --- | --- | --- |
| Changed a file, not committed, want it back as it was | `git restore file` | Yes. Nothing was shared. |
| Staged something by accident | `git restore --staged file` | Yes |
| Last commit's message is wrong, or forgot a file | `git commit --amend` | **No.** Only before pushing. |
| Last commit was a mistake, not pushed | `git reset --soft HEAD~1` | **No.** Only before pushing. |
| A commit that's already been pushed | `git revert <commit>` | **Yes.** This is what it's for. |

<Callout kind="warn" title="Commands that throw work away">
`git restore file` and `git reset --hard` discard uncommitted changes permanently. They're not in the reflog, because they were never committed. Read twice before running them.
</Callout>

## Why revert is the safe choice once it's shared

`amend` and `reset` **rewrite history**: they replace commits with new ones. That's fine on your laptop. But if teammates already have the old commits, their copies now disagree with the remote, and things get confusing fast.

`revert` doesn't rewrite anything. It adds a **new** commit that does the opposite of the bad one. History only moves forward, so everyone can just pull.

## The safety net: reflog

Deleted a branch? Reset too far? `git reflog` lists everywhere HEAD has been recently, including commits that no longer appear in `git log`. Find the one you want, and get it back with `git switch -c rescued <id>`.

## The mistake revert can't fix

If a password or API key was pushed, undoing the commit doesn't help. It's still in the history, and anyone who pulled or scanned the repository has it. The only real fix is to **revoke the key and make a new one**. Cleaning the history afterwards is good housekeeping, not a rescue.

<ConsultantNote>
When something goes wrong on a client's project, staying calm and knowing the safe undo is worth a lot. "Revert first, investigate after" gets a broken site working again in minutes, without anyone rewriting history in a panic.
</ConsultantNote>
