## Small scripts, big savings

You now know enough Python to write genuinely useful programs. The most valuable ones are often tiny: 20 to 50 lines that remove a boring manual job someone does every week.

Good candidates are tasks that are:

- **Repetitive**: the same steps every week or month.
- **Rule-based**: you could write the steps down for someone else to follow.
- **On a computer**: combining spreadsheets, renaming files, checking data, producing reports.

If a person spends an hour a week copying numbers from one spreadsheet into another, a 30-line script can save them 50 hours a year.

## The shape of most scripts

Almost every small script follows the same three steps:

```text
read the data  →  work something out  →  write the result
```

| Step | Common tools |
| --- | --- |
| **Read** | `open()` for text files, `csv` for spreadsheet exports, `json` for data from other programs |
| **Work it out** | Loops, `if`, dictionaries for grouping, `sum`, `sorted` |
| **Write** | `open(..., "w")` to save a file, or `print()` to show it |

Keeping these three steps in separate functions, as the exercise does, makes each one easy to test and fix.

## CSV files

Spreadsheet programs like Excel and Google Sheets can save, or "export", a sheet as **CSV** (comma-separated values). It's plain text: one row per line, with commas between the values. The first line holds the column names.

```text
date,category,description,amount
2026-03-01,Travel,Train to client,42.50
2026-03-02,Software,Design tool,15.00
```

Python's built-in `csv` module reads this. `csv.DictReader` gives you each row as a **dictionary**, using the column names as keys:

```python
{"date": "2026-03-01", "category": "Travel", "description": "Train to client", "amount": "42.50"}
```

Notice the amount is `"42.50"`, in quotes: **text**. Everything from a CSV arrives as text, just as you learned in the first Python lesson. Convert it with `float()` before doing maths with it.

In the exercise, `read_rows` does the reading for you. It uses two more tools (`io.StringIO` lets the csv module read from a string instead of a file, and `list(...)` collects all the rows into a list) but you don't need to change it.

## Grouping with a dictionary

"Total spent per category" needs a running total for **each** category. A dictionary does that perfectly: one key per category, holding that category's total so far.

```python
totals = {}
for row in rows:
    key = row["category"]
    if key not in totals:
        totals[key] = 0
    totals[key] = totals[key] + float(row["amount"])
```

Walk through it:

1. Start with an empty dictionary, `{}`.
2. For each row, find its category.
3. `key not in totals` asks: "is there no entry for this category yet?" The word **`in`** checks whether a key exists in a dictionary (or an item is in a list). `not in` is the opposite. If it's a new category, start its total at 0.
4. Add this row's amount to that category's total.

After the first Travel row, totals is `{"Travel": 42.5}`. After the Software row, `{"Travel": 42.5, "Software": 15.0}`. And so on.

The same pattern gives totals per customer, per month, per anything. It's one of the most useful shapes in all of programming.

<details>
<summary>Quick check: why does the code set `totals[key] = 0` before adding?</summary>

Because you can't add to a key that doesn't exist yet: `totals["Travel"] + 42.5` would be a KeyError the first time. Starting each new category at 0 avoids that.
</details>

## Sorting

`sorted(...)` gives back a sorted copy. Given a dictionary, it gives the keys in order, alphabetically for text:

```python
sorted({"Travel": 94.5, "Food": 31.2, "Software": 24.99})
# ["Food", "Software", "Travel"]
```

So `for category in sorted(totals):` goes through the categories alphabetically.

## Writing files

```python
with open("report.txt", "w") as f:
    f.write("Travel: 94.50\n")
    f.write("Food: 31.20\n")
```

- `open("report.txt", "w")` opens a file for **writing**. `"w"` creates the file, or **replaces** everything in it if it exists. `"a"` (append) adds to the end instead.
- `with ... as f:` names the open file `f` for the indented block, and **closes it properly** when the block ends. Always open files this way.
- `f.write(...)` writes text into the file. It doesn't add a line break by itself.
- `\n` inside a string means "new line". So each `write` ending in `\n` produces one line.

Put it together with an f-string and `:.2f`, and you can write a neat report line for each category.

<Callout kind="warn" title="Scripts repeat mistakes perfectly">
A bug in a script that changes data gets applied to every row, instantly. Always run new scripts on a **copy** of the data first, and keep a backup of the original.
</Callout>
