## Many values, one name

A **list** holds values in order:

```python
scores = [72, 45, 90]
names = ["Ada", "Grace", "Linus"]
```

| Code | Gives |
| --- | --- |
| `names[0]` | `"Ada"`, the first item. Counting starts at 0. |
| `names[-1]` | `"Linus"`, the last item |
| `len(names)` | `3`, how many items |
| `names.append("Margaret")` | Adds an item to the end |

## Doing something for each item

A `for` loop runs its indented block once per item:

```python
for name in names:
    print(f"Hello, {name}")
```

That prints three lines. On each pass, `name` holds the next item. To repeat something a set number of times, use `range`: `for i in range(3):` gives 0, 1, 2.

## The patterns you'll see everywhere

Almost every loop in real code is one of a few shapes:

```python
# Running total
total = 0
for price in prices:
    total = total + price

# Counting
count = 0
for score in scores:
    if score >= 50:
        count = count + 1

# Building a new list
passed = []
for score in scores:
    if score >= 50:
        passed.append(score)
```

Spotting the pattern is most of reading a loop. Notice that the variable always starts **before** the loop, the work happens **inside**, and the result is used **after**.

<Callout title="Python's shortcuts">
Python has built-in shortcuts for common jobs: `sum(prices)`, `max(scores)`, `min(scores)`, and `sorted(names)`. Experienced programmers use them a lot, but they're doing the same loops underneath. Knowing the loop helps you read both.
</Callout>

<ConsultantNote>
Loops are where performance problems hide. A loop that asks the database a question for every one of 10,000 customers can turn a one-second page into a one-minute page. When a client says "it's slow", look for loops doing expensive work.
</ConsultantNote>
