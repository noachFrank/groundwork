## Why JavaScript

JavaScript is the only language that runs in every web browser. Every interactive website uses it. With **Node.js**, the program that runs Groundwork, it also runs servers. So whether a client's project is a website, a web app or an API, you'll meet JavaScript, or TypeScript, which is JavaScript with type labels added.

The good news: you already know the ideas. Variables, if, loops, functions, lists and dictionaries all exist in JavaScript. Mostly the punctuation is different.

## Side by side

```python
# Python
def shipping_cost(total, international):
    if international:
        return 15
    elif total >= 50:
        return 0
    else:
        return 5

name = "Ada"
print(f"Hello {name}")
```

```javascript
// JavaScript
function shippingCost(total, international) {
  if (international) {
    return 15;
  } else if (total >= 50) {
    return 0;
  } else {
    return 5;
  }
}

const name = "Ada";
console.log(`Hello ${name}`);
```

| Python | JavaScript |
| --- | --- |
| Indentation groups lines | `{ }` braces group lines. Indentation is just for people. |
| `# comment` | `// comment` |
| `elif` | `else if` |
| `True`, `False`, `None` | `true`, `false`, `null`, and also `undefined` |
| `print(x)` | `console.log(x)` |
| `f"Hi {name}"` | `` `Hi ${name}` `` (backticks) |
| `name = "Ada"` | `const name = "Ada"` or `let count = 0` |
| `shipping_cost` | `shippingCost`. JavaScript names usually use "camelCase". |
| list `[1, 2]` | array `[1, 2]` |
| dictionary `{"a": 1}` | object `{ a: 1 }`, read with `obj.a` |

## const and let

JavaScript makes you announce new variables. `const` is for values that won't be reassigned, and `let` is for ones that will, like a running total. You'll also see `var` in older code. It behaves in confusing ways, so avoid it in new code.

## The two traps

**Automatic type conversion.** Python stops you mixing text and numbers. JavaScript converts silently: `"5" + 1` is `"51"`, but `"5" - 1` is `4`. Data from forms and web requests often arrives as text, so convert on purpose with `Number(...)`.

**`==` versus `===`.** `==` converts before comparing, so `"" == 0`, `"1" == 1` and `null == undefined` are all true. `===` compares exactly. **Always use `===`** (and `!==`).

<ConsultantNote>
JavaScript's loose rules are a big reason TypeScript has become the default on serious projects. It catches many type mistakes before the code runs. If a client's large JavaScript codebase keeps having "undefined" bugs, gradually moving to TypeScript is a common recommendation.
</ConsultantNote>
