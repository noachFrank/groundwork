## One language, two homes

JavaScript started in the browser, where it makes pages interactive. **Node.js** lets the same language run as a normal program on a computer or server. Groundwork is a Node program, and you've been running Node since the PATH lesson.

| | Browser JavaScript | Node.js |
| --- | --- | --- |
| Runs | Inside a web page | In a terminal, or as a server |
| Can change the page | Yes | There's no page |
| Can read and write your files | No, for your safety | Yes |
| Used for | Websites and web apps | Servers, APIs, tools and scripts |

Want to try browser JavaScript right now? In your browser, press **F12** to open the developer tools, click **Console**, type `2 + 2` and press Enter. Every browser has a JavaScript console built in.

## Waiting without freezing

Some things take time: a network request, reading a big file, a database query. JavaScript doesn't stop and wait for them, because then a web page would freeze, or a server could only help one person at a time. Instead, slow operations give back a **promise**: "I'll have the answer later."

`await` is how you wait for a promise in readable, top-to-bottom code:

```javascript
async function main() {
  const response = await fetch("http://localhost:4314/orders");  // wait for the reply
  const orders = await response.json();                          // wait for the body
  console.log(orders.length);
}
```

- A function that uses `await` must be marked **`async`**.
- Forgetting `await` is a classic bug: you get a promise, not the data, and things like `.json()` or `.length` don't work as expected.

You'll see `async` and `await` all over modern JavaScript, in browsers and in Node.

## Reading Node errors

When something fails, Node prints an error and a **stack trace**, its version of Python's traceback. The details differ, but you read it the same way: the error name and message first, then the lines showing where it happened.

```text
TypeError: fetch failed
    at ... report.js:4:26
  [cause]: Error: connect ECONNREFUSED 127.0.0.1:4399
```

`ECONNREFUSED` means **connection refused**: nothing was listening on that port. You learned exactly why in the ports lesson.

<ConsultantNote>
Most of a modern web app's backend is code like your script: receive a request, await a database or another API, reshape the data, send it back. Missing awaits and unhandled failures, like a fetch to a service that's down, are common causes of mysterious production errors.
</ConsultantNote>
