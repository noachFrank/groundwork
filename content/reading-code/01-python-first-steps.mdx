## What a program is

A program is a list of instructions that the computer follows **in order, from the top**. That's all. Everything else, from loops to functions to whole apps, is a way of organizing those instructions.

This module's goal is **reading** code: understanding what it does, spotting what's wrong, and judging code that someone else, or an AI, wrote. You'll write some too, because writing is the best way to learn reading.

We start with Python because it reads almost like English. Then JavaScript, the language of the web.

## Values and their types

Every value has a **type**, and the type decides what you can do with it:

| Type | Example | What it is |
| --- | --- | --- |
| `str` | `"hello"`, `"30"` | Text. Always in quotes. |
| `int` | `42`, `-7` | A whole number |
| `float` | `3.5`, `0.1` | A number with a decimal point |
| `bool` | `True`, `False` | Yes or no |

`"30"` and `30` look alike but behave differently. `"30" + "1"` is `"301"`, and `30 + 1` is `31`. Mixing them, `"30" + 1`, is an error. This one detail causes a surprising share of real bugs.

## Variables

A **variable** gives a value a name:

```python
price = 3.5
quantity = 2
total = price * quantity     # 7.0
```

Read `=` as "store". The right side is worked out first, then stored under the name on the left. That's why `count = count + 1` makes sense: take the old count, add one, store it back.

Lines starting with `#` are **comments**: notes for people, ignored by Python.

## Showing results

`print()` shows a value. **f-strings** are the neat way to mix values into text:

```python
name = "Ada"
total = 7.0
print(f"{name}, your total is {total}")   # Ada, your total is 7.0
```

<Callout title="Reading tip">
When you read code, say each line out loud in plain English: "store 3.5 as price", "store price times quantity as total". If you can't say what a line does, that's the line to look up.
</Callout>
