## What a program is

A program is a list of instructions that the computer follows **one line at a time, in order, from the top**. That's all. Everything else you'll learn, from decisions to loops to whole apps, is a way of organizing those instructions.

```python
print("First")
print("Second")
print("Third")
```

That prints three lines, in that order, every time. When you read code, read it the way the computer does: top to bottom, one line at a time.

## How the Python exercises work

Groundwork runs Python **inside the app**, in your browser, so there's nothing to install. Each Python exercise has:

- **An editor**: a box where you type code. It starts with some **starter code**, usually with comments (lines starting with `#`) telling you what to do.
- **A Run and check button.** It runs your code from top to bottom. Anything your code prints appears underneath. Then **hidden checks** test your code and tell you which parts are right, and what's wrong with the rest.
- **Error messages**, if your code can't run. Python's errors appear underneath, like the ones in the terminal. Read the last line first: it says what went wrong.

You can run as many times as you like. Getting checks wrong is part of the process, not a failure.

## Values and their types

Every piece of data in a program is a **value**: a number, some text, and so on. Every value has a **type**, and the type decides what you can do with it.

| Type | Example | What it is |
| --- | --- | --- |
| `str` (string) | `"hello"`, `"30"` | Text. Always in quotes, either `"double"` or `'single'`. |
| `int` (integer) | `42`, `-7`, `0` | A whole number |
| `float` | `3.5`, `0.1`, `-2.25` | A number with a decimal point |
| `bool` (Boolean) | `True`, `False` | Yes or no. Capital T and F. |

**Text is always in quotes.** That's how Python tells text apart from everything else. `"30"` and `30` look alike, but one is text and the other is a number, and they behave completely differently.

## Arithmetic

Numbers work like a calculator:

| Symbol | Means | Example | Result |
| --- | --- | --- | --- |
| `+` | add | `7 + 2` | `9` |
| `-` | subtract | `7 - 2` | `5` |
| `*` | multiply | `7 * 2` | `14` |
| `/` | divide | `7 / 2` | `3.5` |

Multiplying and dividing happen before adding and subtracting, as in school maths: `2 + 3 * 4` is `14`, not `20`. Use brackets to change the order: `(2 + 3) * 4` is `20`.

`+` also works on text, but it **joins** instead of adding: `"Hello, " + "Ada"` is `"Hello, Ada"`. So `"30" + "1"` is `"301"`, while `30 + 1` is `31`.

<details>
<summary>Quick check: what's `"2" + "2"`? And `2 + 2`?</summary>

`"2" + "2"` is `"22"`: two pieces of text joined. `2 + 2` is `4`.
</details>

## Variables

A **variable** gives a value a name, so you can use it later. You met the idea in the shell. Python's version:

```python
price = 3.5
quantity = 2
total = price * quantity
```

Read `=` as **"store"**, not "equals". The line `total = price * quantity` means: work out `price * quantity` (that's 7.0), then store the answer under the name `total`.

Python always works out the **right side first**, then stores it under the name on the left. That's why this line makes sense, even though it looks like bad maths:

```python
count = 5
count = count + 1     # take the old count (5), add 1, store 6 back in count
```

A variable can hold a new value at any time. The old one is simply replaced.

Variable names can use letters, numbers and underscores, but no spaces, and can't start with a number. Python programmers write multi-word names with underscores, like `coffee_price`. Names are case-sensitive: `Price` and `price` are different variables.

<details>
<summary>Quick check: after `a = 10`, then `a = a - 3`, what's in `a`?</summary>

`7`. The right side, 10 minus 3, is worked out first, then stored back in `a`.
</details>

## Showing results

`print()` shows a value on the screen, below your code:

```python
print("Hello")        # Hello
print(2 + 2)          # 4
print(total)          # 7.0
```

The value goes between the round brackets. You can print text, numbers, variables, or a calculation.

### f-strings: values inside text

Very often you want to mix values into a sentence. An **f-string** does that. Put an `f` right before the opening quote, then put any variable or calculation inside curly brackets `{ }`:

```python
name = "Ada"
total = 7.0
print(f"{name}, your total is {total}")   # Ada, your total is 7.0
```

Python replaces each `{...}` with its value. Without the `f`, you'd literally get the text `{name}` on screen. That's the most common f-string mistake.

## Text and numbers don't mix

What happens here?

```python
age = "30"
next_year = age + 1
```

Python stops with an error:

```text
TypeError: can only concatenate str (not "int") to str
```

Read it in pieces: `TypeError` means a value was the wrong type for what you asked. "Concatenate" is a programmer's word for joining text. So: "I can only join text to text, and you gave me a number." Because of the quotes, `age` holds the **text** "30", and Python won't guess whether you meant 31 or "301".

Converting between types fixes it:

| Function | Turns | Into | Example |
| --- | --- | --- | --- |
| `int(...)` | text | a whole number | `int("30")` is `30` |
| `float(...)` | text | a decimal | `float("3.5")` is `3.5` |
| `str(...)` | a number | text | `str(30)` is `"30"` |

So `next_year = int(age) + 1` works, and gives 31.

This matters far beyond this example. **Anything typed by a user, or read from a file or a web page, arrives as text**, even if it looks like a number. Converting it is something real code does constantly.

<Callout title="Reading tip">
When you read code, say each line out loud in plain English: "store 3.5 as price", "store price times quantity as total". If you can't say what a line does, that's the line to look up, or ask about.
</Callout>
