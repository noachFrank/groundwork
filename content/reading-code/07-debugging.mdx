## The worst bugs don't crash

A crash at least tells you where to look. The bugs that cost clients money usually **don't** crash: they give a slightly wrong price, skip a customer, or fail only for some people. Finding those takes a method, not luck.

## The method

1. **Reproduce it.** Find a small example where you know the right answer and can make the wrong one happen every time. If you can't reproduce it, you can't confirm a fix.
2. **Narrow it down.** Which part of the program is it in? Cut the problem in half: is the data right going into this function? Coming out?
3. **Look at the real values.** Don't assume. Add `print()` calls, or use a debugger, to see what variables actually hold.
4. **Fix the cause**, not the symptom.
5. **Check it's fixed.** Run the same reproduction. Then check you haven't broken anything nearby, and look for the same mistake elsewhere.

## Print debugging

The simplest tool is still one of the best. Add temporary prints to see inside:

```python
def get_page(items, page_number, per_page):
    start = page_number * per_page
    end = start + per_page
    print("page", page_number, "start", start, "end", end)   # temporary
    return items[start:end]
```

Seeing `page 1 start 3 end 6` makes the bug obvious: page 1 should start at 0. Remove the prints once you've fixed it.

Editors like VS Code have a proper **debugger**, which pauses the program on a line and lets you inspect every variable. It's the same idea with more power.

## Useful habits

- **Change one thing at a time.** Otherwise you won't know which change fixed it, or broke something else.
- **Ask "what changed?"** A bug that started last Tuesday usually comes from something that changed last Tuesday. `git log` tells you what.
- **Explain it out loud.** Rubber duck debugging, from the first module, works remarkably well.
- **Take a break.** Fresh eyes find bugs that tired ones stare straight past.

<Callout title="Asking AI to debug">
AI can be good at spotting bugs, if you give it what you'd give a person: the code, the input, what you expected, and what actually happened. "It doesn't work" gets a guess. "For page 1 I expected Lamp, Desk, Chair but got Shelf, Rug, Clock" usually gets the answer.
</Callout>

<ConsultantNote>
Clients rarely report bugs precisely. "It's broken sometimes" is normal. Turning that into "it fails for surnames with apostrophes since last Tuesday's update" is a valuable skill. It's careful questions plus this method, and it's what makes clients trust you with their systems.
</ConsultantNote>
