## In this lesson

- Why JavaScript matters so much.
- The same ideas you know from Python, written the JavaScript way, side by side.
- JavaScript **objects** and **arrays**, its versions of dictionaries and lists.
- The two traps that only JavaScript has, and the habits that avoid them.

## Why JavaScript

You met JavaScript in *Code, languages, and the programs that run them*: it's the only language every web browser can run, so every interactive website uses it. With **Node.js**, the program that runs Groundwork, it also runs servers and scripts. So whether a client's project is a website, a web app or a backend, you'll meet JavaScript, or **TypeScript**, which is JavaScript with extra type labels added (more on that at the end).

The good news: you already know the ideas. Variables, decisions, loops, functions, lists and dictionaries all exist in JavaScript. Mostly, the punctuation is different. This lesson is a translation guide.

JavaScript exercises work just like the Python ones. Write your code, press **Run and check**, and anything you `console.log` appears underneath, followed by the checks.

## Side by side

Here's the same small program in both languages:

```python
# Python
def shipping_cost(total, international):
    if international:
        return 15
    elif total >= 50:
        return 0
    else:
        return 5

name = "Ada"
print(f"Hello {name}")
```

```javascript
// JavaScript
function shippingCost(total, international) {
  if (international) {
    return 15;
  } else if (total >= 50) {
    return 0;
  } else {
    return 5;
  }
}

const name = "Ada";
console.log(`Hello ${name}`);
```

Walk through the differences, line by line:

- **`function`** instead of `def`, and the parameters in brackets as before.
- **Curly braces `{ }`** group lines instead of a colon plus indentation. Everything between `{` and its matching `}` belongs together. JavaScript programmers still indent, but only for people to read. The braces are what count.
- **Conditions go in round brackets:** `if (international)`, not `if international:`.
- **`else if`** instead of `elif`.
- **Semicolons `;`** end most lines, like a full stop. JavaScript can often guess where they go, but writing them is the norm.
- **`//`** starts a comment instead of `#`.
- **`const name = ...`** announces a new variable (more below).
- **`console.log(...)`** instead of `print(...)`.
- **Backticks** and `${...}` instead of `f"..."` and `{...}`. These are called **template literals**.

<details>
<summary>Quick check: how do you write Python's `elif total >= 50:` in JavaScript?</summary>

`} else if (total >= 50) {` with the condition in round brackets, and braces around the block.
</details>

## The full translation table

| Python | JavaScript |
| --- | --- |
| Indentation groups lines | `{ }` braces group lines |
| `# comment` | `// comment` |
| `def name(a, b):` | `function name(a, b) {` |
| `if x:` / `elif` / `else:` | `if (x) {` / `else if` / `else {` |
| `True`, `False`, `None` | `true`, `false`, `null`, and also `undefined` |
| `print(x)` | `console.log(x)` |
| `f"Hi {name}"` | `` `Hi ${name}` `` (backticks) |
| `name = "Ada"` | `const name = "Ada"` or `let count = 0` |
| `shipping_cost` | `shippingCost`. JavaScript names usually use **camelCase**: no underscores, and a capital at the start of each new word. |
| list `[1, 2]` | **array** `[1, 2]` |
| dictionary `{"a": 1}`, read with `d["a"]` | **object** `{ a: 1 }`, read with `obj.a` |
| `for price in prices:` | `for (const price of prices) {` |
| `len(items)` | `items.length` |

## const and let

JavaScript makes you **announce** a new variable the first time you create it:

- **`const`** for a value that won't be replaced: `const name = "Ada";`
- **`let`** for one that will be, like a running total: `let total = 0;` then later `total = total + price;`

After the first line, you just use the name, without `const` or `let`. Using `const` where you can makes code easier to read, because you know that name will always mean the same thing.

You'll also see `var` in older code. It behaves in confusing ways, so avoid it in new code.

## Objects and arrays

A JavaScript **object** is like a Python dictionary. The keys usually don't need quotes, and you read values with a **dot**:

```javascript
const order = { customer: "Ada", items: 2, paid: true };

order.customer      // "Ada"
order.items         // 2
order["customer"]   // also "Ada": square brackets work too
order.phone         // undefined: no such key, but no crash
```

This is why JSON looks the way it does: JSON started life as JavaScript's way of writing objects.

A JavaScript **array** is like a Python list: `[10, 20, 30]`, counted from 0, with `.length` for how many items there are. Loop over one with `for...of`:

```javascript
let total = 0;
for (const price of [10, 20, 30]) {
  total = total + price;
}
// total is 60
```

That's the running-total pattern, in JavaScript.

## null and undefined

Python has one "nothing" value, None. JavaScript has two:

- **`null`**: someone deliberately set "no value".
- **`undefined`**: nothing was ever set. A missing object key, a variable with no value yet, or a function that didn't `return`, all give `undefined`.

Where Python crashes with a KeyError, JavaScript quietly gives `undefined`, and the problem shows up later. That's a theme with JavaScript.

## The two traps

### Silent type conversion

Python stops you mixing text and numbers with a TypeError. JavaScript doesn't stop you. It **converts** silently, following rules that can surprise you:

```javascript
"5" + 1     // "51"   + with text joins
"5" - 1     // 4      - has no text meaning, so it converts to a number
"5" * "2"   // 10
```

Data from forms, web pages and URLs arrives as text. In JavaScript, convert it on purpose before doing maths, with **`Number(...)`**: `Number("4.50")` is `4.5`. The second task is exactly this bug.

### == versus ===

JavaScript has two kinds of "equals":

- `==` converts both sides first, then compares. So `"" == 0`, `"1" == 1` and `null == undefined` are all **true**.
- `===` compares exactly, with no converting. `"1" === 1` is **false**.

**Always use `===`** (and `!==` for "not equal"). `==` causes bugs that are very hard to spot.

<details>
<summary>Quick check: what's `"10" + 5` in JavaScript? And `"10" === 10`?</summary>

`"10" + 5` is `"105"`, because `+` with text joins. `"10" === 10` is `false`, because one is text and one is a number.
</details>

## TypeScript

These loose rules are a big reason **TypeScript** has become the standard on serious projects. TypeScript is JavaScript plus **type labels**: you write `let total: number = 0`, and a tool checks, before the code runs, that you never put text in `total`. Then it removes the labels and gives plain JavaScript. Files end in `.ts`. Groundwork itself is written in TypeScript.

<ConsultantNote>
If a client's large JavaScript codebase keeps having "undefined" bugs, gradually moving to TypeScript is a common recommendation. It catches many type mistakes before the code ever runs.
</ConsultantNote>
