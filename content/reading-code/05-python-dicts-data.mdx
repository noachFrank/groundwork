## Values with labels

A list stores values by position. A **dictionary** stores them by **key**, a label:

```python
order = {"customer": "Ada", "total": 49, "paid": True}

order["customer"]          # "Ada"
order["total"] = 55        # change a value
order["city"] = "London"   # add a new key
order.get("phone")         # None, because there's no phone, but no crash either
```

`order["phone"]` would crash with a **KeyError**, one of the most common errors in real code, because real data is often missing fields.

## The shape of real data

Real data is lists and dictionaries **nested inside each other**:

```python
orders = [
    {"customer": "Ada", "items": [{"name": "Keyboard", "price": 49}, {"name": "Mouse", "price": 9}]},
    {"customer": "Grace", "items": [{"name": "Monitor", "price": 189}]},
]

orders[0]["items"][1]["price"]    # 9
```

Read nested lookups **one step at a time**, left to right: the first order, its items, the second item, its price.

Looping over this kind of data is the bread and butter of programming:

```python
for order in orders:
    for item in order["items"]:
        print(order["customer"], item["name"])
```

## JSON is the same shape

**JSON**, which you met in the APIs lesson, is how this data travels between programs. It maps directly onto Python:

| JSON | Python |
| --- | --- |
| `{ "key": value }` (object) | dictionary |
| `[ 1, 2, 3 ]` (array) | list |
| `true`, `false`, `null` | `True`, `False`, `None` |

`json.loads(text)` turns JSON text into Python data, and `json.dumps(data)` turns it back.

<ConsultantNote>
Most "integration" work, connecting one system to another, is exactly this: reading nested data from one system, picking out fields, and reshaping it for another. And most integration bugs are a missing key, a field that's sometimes null, or a number that arrives as text.
</ConsultantNote>
