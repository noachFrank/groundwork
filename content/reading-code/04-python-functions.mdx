## A function is a named recipe

A **function** packages some code under a name, so you can use it again and again:

```python
def shipping_cost(order_total):
    if order_total >= 50:
        return 0
    return 5

print(shipping_cost(20))   # 5
print(shipping_cost(80))   # 0
```

- `def` starts it. `shipping_cost` is its name.
- `order_total` is a **parameter**: a name for whatever value is passed in.
- `return` hands the answer back, and ends the function right there.
- `shipping_cost(20)` **calls** it with 20 as the input.

## return versus print

This is the most common beginner confusion, so it's worth getting firmly:

| | `print(x)` | `return x` |
| --- | --- | --- |
| Who is it for? | A person looking at the screen | The code that called the function |
| Can other code use the value? | No | Yes |
| Does the function stop? | No | Yes |

```python
def add_printing(a, b):
    print(a + b)       # shows 5, gives back None

def add_returning(a, b):
    return a + b       # gives back 5

x = add_printing(2, 3)    # screen shows 5, but x is None
y = add_returning(2, 3)   # y is 5, and you can keep using it
```

A function that falls off its end without a `return` gives back **None**. That's often how None sneaks into a program and causes a crash somewhere far away.

## Why functions matter for reading code

Real programs are made of hundreds of functions calling each other. Good function names make code readable: `calculate_tax(order)` tells you what's happening without reading inside. When you read unfamiliar code, start with the function names and what they return, and only dig into the inside of the ones you need.

<ConsultantNote>
A function called `get_user` that also deletes old records, or `calculate_total` that quietly sends an email, is a warning sign in a code review. Functions should do what their name says, and nothing surprising. Spotting names that lie is part of judging code quality.
</ConsultantNote>
