- How to write one with `def`, give it inputs called **parameters**, and hand back an answer with `return`.
- How to **call** a function, as many times as you like.
- Why **indentation**, the spaces at the start of a line, matters so much in Python.
- How the exercises in the rest of this module are set up, so they make sense from now on.

This lesson goes slowly on purpose. Every Python exercise after it uses functions.

## A function is a small machine

Imagine a machine in a café: put in a price, and it gives you back the price with tax added. You don't need to know how it works inside. You just use it, as often as you like, with any price.

A **function** is that machine, in code. It's a named piece of code that:

- **takes some values in**,
- **does some work** with them,
- and **gives an answer back**.

You've already used functions without knowing it. `print(...)` is a function: you give it a value, and it shows it. `int(...)` is a function: you give it text like `"30"`, and it gives back the number 30. Those were written for you. Now you'll write your own.

## Writing one

Here's a complete function:

```python
def price_with_tax(price):
    total = price * 1.2
    return total
```

Line by line:

| Line | What it means |
| --- | --- |
| `def price_with_tax(price):` | "**Def**ine a new function called `price_with_tax`. When it's used, it will be given one value, and inside the function that value will be called `price`." The line **must** end with a colon `:`. |
| `    total = price * 1.2` | Indented, so it's part of the function. Works out the price plus 20% and stores it as `total`. |
| `    return total` | Indented too. Hands the value of `total` **back** to whoever used the function, and ends the function. |

The name in brackets, `price`, is a **parameter**: a placeholder name for a value the function will be given later. It works like a variable that only exists inside the function.

### Defining isn't running

This is the part that surprises people. Writing a `def` **doesn't run anything**. It just builds the machine and gives it a name, ready for later. If your program were only the three lines above, nothing would happen at all.

<details>
<summary>Quick check: what's the parameter in `def greeting(name):`?</summary>

`name`. It's the placeholder for whatever value the function is given when it's called.
</details>

## Calling it

To use a function, you **call** it: write its name, followed by round brackets with the value inside.

```python
price_with_tax(10)
```

When Python reaches that line, it:

1. Jumps into the function.
2. Sets `price` to `10`.
3. Runs the indented lines: `total` becomes `12.0`.
4. Hits `return total`, and jumps back with the answer, `12.0`.

The value you put in the brackets when calling, here `10`, is called an **argument**. So: the **parameter** is the name in the `def` line, and the **argument** is the actual value you pass in.

The call itself becomes the returned value, so you can use it anywhere you'd use a value:

```python
print(price_with_tax(10))          # 12.0
bill = price_with_tax(50)          # bill is now 60.0
both = price_with_tax(10) + price_with_tax(50)   # 72.0
```

Write the machine once, use it as often as you like, with any value.

<details>
<summary>Quick check: after `bill = price_with_tax(100)`, what's in `bill`?</summary>

`120.0`. The function returns 100 * 1.2, and that's stored in `bill`.
</details>

## More than one parameter

A function can take several values. Separate them with commas, both in the `def` line and when calling:

```python
def rectangle_area(width, height):
    return width * height

rectangle_area(3, 4)    # width is 3, height is 4, gives back 12
```

They're matched up **in order**: the first argument goes to the first parameter, the second to the second.

Notice this function's body is a single line. You can return a calculation directly, without storing it in a variable first.

## Indentation is part of the code

In Python, the spaces at the start of a line aren't just for looks. They decide **what belongs to what**.

Every line that's part of a function must be indented under its `def` line. The usual amount is **four spaces** (in Groundwork's editor, pressing **Tab** puts in four spaces for you). The function ends at the first line that isn't indented any more:

```python
def add_tax(price):
    total = price * 1.2     # inside the function
    return total            # inside the function

print(add_tax(10))          # NOT indented: outside, runs after the def
```

Get the indentation wrong and Python either refuses to run, with an `IndentationError`, or, worse, runs a line at the wrong time. Many other languages use curly brackets `{ }` to group lines. Python uses indentation instead. You'll see the same idea again with `if` and loops.

## `pass`: an empty placeholder

Python doesn't allow a function with nothing inside it. So when you want an empty function, to fill in later, you write `pass`, which means "do nothing":

```python
def greeting(name):
    pass
```

Exercises often give you functions like this. Your job is to **replace `pass`** with real code.

## `None`: the answer when there's no answer

A function that never reaches a `return` line still gives something back: a special value called **`None`**, which is Python's word for "nothing".

```python
def greeting(name):
    pass

print(greeting("Ada"))     # None
```

So if a check says your function "gave back None", it means your function never returned anything. Usually `return` is missing, or `pass` is still there.

## Why the exercises use functions

From now on, most Python exercises ask you to finish a function. Here's why. The hidden checks need to try your code **many times with different values**, including tricky ones, like an empty list or a number exactly on a boundary. A function makes that easy: the checks just call it again and again, each time with different arguments, and compare what it returns with the right answer.

So when you see:

```python
def shipping_cost(order_total, is_international):
    # Your code goes here
    return 0
```

read it as: "Write code that works out the shipping cost for **any** order_total and is_international, and `return` the answer." The `print` lines at the bottom of the starter are just there so you can see what your function returns.

<ConsultantNote>
Real programs are made of hundreds of functions calling each other. Good function names make code readable: `calculate_tax(order)` tells you what's happening without reading inside it. When you read unfamiliar code, start with the function names, what goes in, and what comes back. Then dig into only the ones you need.
</ConsultantNote>
