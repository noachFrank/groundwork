## In this lesson

- The difference between JavaScript in a browser and JavaScript in Node.
- How a Node program uses built-in tools, like reading and writing files.
- How JavaScript **waits** for slow things, like a reply from another program, without freezing: **promises**, `async` and `await`.
- How to read a Node error.
- You'll write a script that asks an API for data, adds it up, and writes a report.

## One language, two homes

JavaScript started in the browser, where it makes pages interactive. **Node.js** lets the same language run as an ordinary program on a computer or server. You've been running Node since *Code, languages, and the programs that run them*, and Groundwork itself is a Node program.

| | Browser JavaScript | Node.js |
| --- | --- | --- |
| Runs | Inside a web page | In a terminal, or as a server |
| Can change the page | Yes | There's no page |
| Can read and write your files | No, for your safety | Yes |
| Used for | Websites and web apps | Servers, APIs, tools and scripts |

Want to try browser JavaScript right now? In your browser, press **F12** to open the **developer tools**, click the **Console** tab, type `2 + 2` and press Enter. Every browser has a JavaScript console built in, and developers use it all the time to test things and read errors.

## Getting Node's built-in tools

Like Python's `import`, Node can load extra modules. The older, very common way is `require`:

```javascript
const fs = require("fs");
fs.writeFileSync("summary.txt", "Total of all orders: 304\n");
```

- `require("fs")` loads Node's built-in **file system** module and stores it as `fs`.
- `fs.writeFileSync(name, text)` writes text into a file, replacing what's there, like Python's `open(name, "w")`.

(Newer code often writes `import fs from "fs"` instead. Same idea.)

## Asking another program for data

In the Python dictionaries lesson you met the idea of an **API**: a program that offers data to other programs, usually as JSON. Groundwork runs a small practice API on your computer, on port 4314. You can see what it gives with curl, from the npm lesson:

```text
curl.exe http://localhost:4314/orders
```

From JavaScript, **`fetch`** does the same job: it sends a request to a web address and gets the response. But a request takes time, and that raises a question.

## Waiting without freezing

Some things take time: a network request, reading a big file, asking a database. Imagine a web page that froze completely every time it waited for data, or a server that could only help one visitor at a time because it was stuck waiting. JavaScript avoids that.

Instead of waiting, a slow operation immediately gives back a **promise**: an object that says "I don't have the answer yet, but I'll have it later." The program can get on with other things meanwhile.

### await: wait for a promise, the readable way

`await` means "pause **this function** here until the promise has its answer, then carry on with the answer". Everything else in the program keeps running.

```javascript
async function main() {
  const response = await fetch("http://localhost:4314/orders");  // wait for the reply
  const orders = await response.json();                          // wait for the body, as JavaScript data
  console.log(orders.length);
}

main();
```

Line by line:

1. `async function main()` defines a function that's allowed to use `await`. A function that uses `await` **must** be marked `async`.
2. `await fetch(...)` sends the request and waits for the response.
3. `await response.json()` waits for the rest of the reply and turns its JSON into JavaScript arrays and objects, like Python's `json.loads`.
4. Now `orders` is a normal array, and you can use `.length`, `reduce`, and so on.
5. `main();` on the last line calls the function. Without it, nothing would run: remember, defining a function doesn't run it.

<details>
<summary>Quick check: what's in `response` if you forget the `await` before `fetch(...)`?</summary>

A promise, not the response. Things like `response.json()` then don't work as expected. Forgetting `await` is one of the most common JavaScript bugs.
</details>

You'll see `async` and `await` all over modern JavaScript, in browsers and in Node. When you read code that talks to anything outside itself, look for them.

## console.log with several values

`console.log("Orders:", orders.length, "Total:", total)` prints several values in one line, separated by spaces, like Python's `print` with commas.

## Reading Node errors

When something fails, Node prints an error and a **stack trace**: its version of Python's traceback. The layout differs, but you read it the same way: the error name and message first, then the lines showing where it happened.

```text
TypeError: fetch failed
    at ... report.js:4:26
  [cause]: Error: connect ECONNREFUSED 127.0.0.1:4399
```

- `TypeError: fetch failed`: the request didn't work.
- `report.js:4:26`: in report.js, line 4, character 26.
- `[cause]`: the reason underneath. `ECONNREFUSED` means **connection refused**: nothing was listening on port 4399 at 127.0.0.1. You learned exactly why that happens in *Programs, processes and ports*.

In the task, you'll cause this error on purpose by pointing the script at the wrong port.

<ConsultantNote>
Most of a modern web app's backend is code like your script: receive a request, await a database or another API, reshape the data, send it back. Missing awaits, and unhandled failures like a fetch to a service that's down, are common causes of mysterious production errors.
</ConsultantNote>
