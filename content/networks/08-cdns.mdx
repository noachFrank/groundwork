  - id: edge-sim
    type: python
    title: Simulate an edge server's cache
    instructions: |
      You'll use: a dictionary, `in`, a `for` loop and arithmetic (from the Python lessons).

      An edge server receives requests over time. Each request is a dictionary like `{"time": 30, "path": "/logo.png"}`, with the time in seconds. A saved copy can be reused for `ttl` seconds after it was fetched from the origin.

      `simulate(requests, ttl)` returns a dictionary `{"hits": …, "misses": …}`. For each request:

      - If the path is in the cache **and** fewer than `ttl` seconds have passed since it was stored, it's a **hit**.
      - Otherwise it's a **miss**: count it, and store the path in the cache with the current time (as if fetched from the origin).
    starter: |
      def simulate(requests, ttl):
          cache = {}
          hits = 0
          misses = 0
          # for each request:
          #   path in cache and request["time"] - cache[path] < ttl -> a hit
          #   otherwise a miss: cache[path] = request["time"]
          return {"hits": hits, "misses": misses}


      day = [
          {"time": 0, "path": "/logo.png"},
          {"time": 10, "path": "/logo.png"},
          {"time": 20, "path": "/app.js"},
          {"time": 70, "path": "/logo.png"},
      ]
      print(simulate(day, 60))
    tests:
      - name: first request is a miss, the next is a hit
        code: |
          got = simulate([{"time": 0, "path": "/a"}, {"time": 5, "path": "/a"}], 60)
          assert got == {"hits": 1, "misses": 1}, f"Expected 1 hit and 1 miss, got {got}."
      - name: different paths are cached separately
        code: |
          got = simulate([{"time": 0, "path": "/a"}, {"time": 1, "path": "/b"}, {"time": 2, "path": "/a"}], 60)
          assert got == {"hits": 1, "misses": 2}, f"/a and /b are different files. Expected 1 hit, 2 misses, got {got}."
      - name: an expired copy is a miss and gets refreshed
        code: |
          got = simulate([{"time": 0, "path": "/logo.png"}, {"time": 10, "path": "/logo.png"}, {"time": 20, "path": "/app.js"}, {"time": 70, "path": "/logo.png"}, {"time": 80, "path": "/logo.png"}], 60)
          assert got == {"hits": 2, "misses": 3}, f"At 70s the logo is 70s old, past the 60s ttl, so it's refetched. Then 80s is a hit. Expected 2 hits, 3 misses, got {got}."
      - name: exactly ttl seconds old counts as expired
        code: |
          got = simulate([{"time": 0, "path": "/a"}, {"time": 60, "path": "/a"}], 60)
          assert got == {"hits": 0, "misses": 2}, f"It must be fewer than ttl seconds old. Expected 0 hits, 2 misses, got {got}."
      - name: a ttl of 0 never hits
        code: |
          got = simulate([{"time": 0, "path": "/a"}, {"time": 0, "path": "/a"}], 0)
          assert got == {"hits": 0, "misses": 2}, f"With ttl 0 nothing may be reused. Got {got}."
    solution: |
      def simulate(requests, ttl):
          cache = {}
          hits = 0
          misses = 0
          for request in requests:
              path = request["path"]
              if path in cache and request["time"] - cache[path] < ttl:
                  hits += 1
              else:
                  misses += 1
                  cache[path] = request["time"]
          return {"hits": hits, "misses": misses}

## In this lesson

Two lessons ago you saw that distance costs time on every round trip. Last lesson you saw how caching headers let a browser reuse a file. A **CDN** combines the two at a worldwide scale:

- What a CDN is: **edge servers** near visitors, and an **origin** behind them.
- **Cache hits and misses**, and the **hit ratio**.
- Getting changes out: **purging**, and **versioned file names**.
- The one thing a CDN must **never** cache.
- How CDNs also absorb **DDoS** attacks.

## Copies near everyone

A **CDN** (content delivery network) is a company with servers in hundreds of cities around the world. Each of these is an **edge server**. When you put a site behind a CDN, its DNS points at the CDN, which sends each visitor to the nearest edge. The site's own server, now called the **origin**, sits behind it all.

Step through what happens:

<Viz name="cdn-cache" />

- On a **cache miss**, the edge doesn't have the file yet (or its copy has expired). It fetches it from the origin, keeps a copy, and answers.
- On a **cache hit**, the edge already has a fresh copy and answers straight away. The origin isn't involved.

The share of requests that are hits is the **hit ratio**. At 95%, only 1 in 20 requests ever reaches the origin. Visitors get files from a few miles away instead of an ocean away, and the origin handles a fraction of the traffic.

Well-known CDNs include Cloudflare, Amazon CloudFront, Akamai, Fastly and Azure Front Door. GitHub Pages, which you used in Stage 1, sits behind one too.

<details>
<summary>Quick check: what happens on a cache miss?</summary>

The edge server doesn't have a fresh copy, so it fetches the file from the origin, keeps a copy for next time, and sends it on to the visitor.
</details>

## The CDN follows your headers

How long does the edge keep a copy? Mostly, as long as the origin's **Cache-Control** header allows, the same header you met in *Faster HTTP*. `max-age=86400` means a day. (CDNs often let you override this in their settings, and some read a separate `s-maxage` meant just for shared caches.)

That's why caching headers matter even more with a CDN. A browser's cache only affects one person. A CDN's cache affects **everyone**.

## Getting changes out

Caching has an obvious downside: you fix a typo in your site's script, and visitors keep getting the old copy until it expires. Two ways out:

1. **Purging.** CDNs let you tell every edge "throw away your copy of `/app.js` now". It's useful in an emergency, but it doesn't reach copies already in visitors' browsers.
2. **Versioned file names.** Put a fingerprint of the file's contents in its name: `app.3f9a1c.js`. When the file changes, so does its name, and so does the page's link to it. No cache anywhere has ever seen the new name, so everyone gets the new file at once. The old one is simply never asked for again.

Versioned names let you set huge max-ages (a year is common) on files, while the HTML page that links to them is cached briefly or not at all. Build tools like Vite do this automatically during `npm run build`. Look in a project's `dist` folder and you'll see names like `index-B3kL9xQa.js`. That's this.

## What a CDN must never cache

A CDN is a **shared cache**: one copy, served to everyone who asks for that address. That's wonderful for a logo and a disaster for a page that's different for each person.

If Ada's account page is cached at `/account`, the next visitor who asks for `/account` gets **Ada's page**. This has happened to real companies, exposing customers' names, addresses and orders. Anything personalized needs:

```text
Cache-Control: private, no-store
```

`private` means only the user's own browser may keep it, and `no-store` means nothing should. The flaw task shows exactly how this goes wrong.

<Callout kind="warn" title="A rule of thumb">
If a response depends on who's logged in, a shared cache must not store it. Cache public files hard, and personal pages not at all.
</Callout>

## More than speed

Because all traffic arrives at the CDN first, it's a natural place for other jobs:

- **TLS termination**: the CDN handles HTTPS and certificates at the edge.
- **DDoS protection**: in a **DDoS** (distributed denial of service) attack, thousands of hijacked machines flood a site with traffic to knock it offline. A single origin server can't survive that, but a CDN's network is enormous, so it can absorb the flood and filter out the junk before it reaches the origin.
- **Firewall rules**: blocking obvious attacks and abusive visitors at the edge. You'll meet this as a "WAF" in the Stage 4 security lessons.

## The simulation task

In the task you'll write the heart of an edge server: a dictionary from path to the time the copy was stored, and the hit-or-miss decision for each request. Notice how quickly the hits add up once popular files are cached. That's why a busy site's hit ratio can be well over 90%.

<ConsultantNote>
A CDN is often the single biggest, cheapest performance win for a client with visitors far from their server, and many have a free tier. But the most common way to break one is "cache everything" with nothing excluded. When you set one up, list what may be cached publicly, check that every logged-in page sends `private` or `no-store`, and test it by logging in as two different users.
</ConsultantNote>
