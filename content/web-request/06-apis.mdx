      import requests

      BASE = "http://localhost:4314"


      def total_spent(customer):
          total = 0
          for order in requests.get(BASE + "/orders").json():
              if order["customer"] == customer:
                  total += order["total"]
          return total


      def find_order(order_id):
          response = requests.get(BASE + "/orders/" + str(order_id))
          if response.status_code == 404:
              return None
          return response.json()

## When the visitor is a program

So far a person has been at one end of the request. An **API** (Application Programming Interface) is the same idea when the visitor is a program. Your weather app, a checkout using Stripe, a dashboard pulling in sales numbers: all APIs.

An API is a promise: "send me a request shaped like this, and I'll answer in this shape." A lot of modern software is mostly services talking to each other this way.

## REST: the most common style

Most web APIs follow a style called **REST**. URLs name things, and the HTTP methods you already know say what to do:

| Request | Meaning |
| --- | --- |
| `GET /orders` | List the orders |
| `GET /orders/102` | Get order 102 |
| `POST /orders` | Create an order |
| `DELETE /orders/102` | Delete order 102 |

## JSON: the shared language

APIs usually send data as **JSON**. It's just text, which nearly every language can read:

```json
{
  "id": 102,
  "customer": "Grace",
  "paid": true,
  "items": ["Monitor", "Cable"]
}
```

Curly braces hold **key and value** pairs. Square brackets hold **lists**. Values can be text, numbers, `true`/`false`, `null`, or more of the same, nested.

## API keys

Many APIs want to know who's calling, usually with a key sent in a header, as you did with `X-API-Key`. Keys let the provider limit and bill usage.

<Callout kind="warn" title="Keep keys out of browser code">
Anything in a web page's code can be read by anyone. A key in there is public. Real keys belong on a server. This is one of the most common mistakes in AI-generated code, so watch for it.
</Callout>

## Where the data lives

Behind most APIs is a database, and a common kind stores data in **tables**. A shop keeps customers in one table and orders in another, with each order holding the id of its customer. **SQL** is the language for asking questions across them.
