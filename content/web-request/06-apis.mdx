## When the visitor is a program

So far, a person with a browser has been at one end of the request. An **API** (Application Programming Interface) is the same idea when the visitor is a **program**. You met the term in the Python dictionaries lesson. Now for how it works.

Your weather app asks a weather company's API for the forecast. A shop's checkout sends card details to a payment company's API. A dashboard pulls sales numbers from an accounting system's API. A lot of modern software is mostly programs talking to each other this way.

An API is a promise: "send me a request shaped like this, and I'll answer in this shape." The shape is written down in the API's **documentation**, which tells you every address, what to send, and what comes back.

## REST: the most common style

Most web APIs follow a style called **REST**. The path names a **thing**, and the HTTP method you already know says **what to do** with it:

| Request | Meaning |
| --- | --- |
| `GET /orders` | List all the orders |
| `GET /orders/102` | Get order 102 |
| `POST /orders` | Create a new order (the details go in the body, as JSON) |
| `DELETE /orders/102` | Delete order 102 |

The answers come back as **JSON**, with a status code saying how it went: `200` for found, `404` if order 102 doesn't exist, and so on.

## Calling an API from Python

The `requests` package, which you saw last lesson, makes this short:

```python
import requests

response = requests.get("http://localhost:4314/orders/102")
response.status_code     # 200
response.json()          # {"id": 102, "customer": "Grace", "item": "Monitor", ...}
```

- `requests.get(address)` sends a GET request and waits for the response.
- `.status_code` is the response's status, as a number.
- `.json()` reads the body as JSON and gives back Python data: a JSON list becomes a list, and a JSON object becomes a dictionary. It's `json.loads` done for you.

If the order doesn't exist, the status code is `404`. Checking it before using the body is a good habit: `if response.status_code == 404: return None`.

<details>
<summary>Quick check: `requests.get(BASE + "/orders")` returns a list of orders. How would you get the first order's customer?</summary>

`requests.get(BASE + "/orders").json()[0]["customer"]`: read the JSON, take item 0, then its "customer" key. Usually you'd store the list in a variable first.
</details>

## API keys

Many APIs want to know **who's calling**, so they can limit, track and bill usage. Usually the caller sends an **API key** (from *Asking good questions*) in a header, such as `X-API-Key: sk_live_...`. You sent one yourself in the HTTP lesson's lab.

<Callout kind="warn" title="Keep keys out of browser code">
Anything in a web page's code can be read by anyone: press F12 and it's all there. A key in frontend JavaScript is a **public** key. Real keys belong on a server, in an environment variable, and the frontend asks your own backend, which then calls the API with the key. This is one of the most common mistakes in AI-generated code, so watch for it.
</Callout>

## Where the data lives

Behind most APIs is a **database**: a program built for storing lots of data safely and finding things in it quickly. A very common kind stores data in **tables**, like spreadsheets: each table has columns, and each row is one record.

A shop might have two tables:

```text
customers                     orders
id | name  | city             id  | customer_id | item     | total | status
---+-------+---------         ----+-------------+----------+-------+-----------
1  | Ada   | London           101 | 1           | Keyboard | 49    | shipped
2  | Grace | New York         102 | 2           | Monitor  | 189   | processing
                              103 | 1           | Mouse    | 9     | delivered
```

Notice orders don't repeat the customer's name and city. Each order holds just the customer's id, in `customer_id`. That's a **foreign key**: a column pointing at a row in another table. It means Ada's details live in exactly one place.

## SQL: asking the database questions

**SQL** (often said "sequel") is the language for asking table databases questions. It reads almost like English. Five words get you a long way:

```sql
SELECT customers.name, orders.item
FROM customers
JOIN orders ON orders.customer_id = customers.id
WHERE orders.total > 20;
```

| Part | Means |
| --- | --- |
| `SELECT customers.name, orders.item` | Which columns to show. `*` means all of them. `table.column` says which table a column is from. |
| `FROM customers` | Which table to start from |
| `JOIN orders ON orders.customer_id = customers.id` | Also bring in the orders table, matching each order to the customer whose id equals its customer_id |
| `WHERE orders.total > 20` | Only keep rows where this is true |
| `;` | The end of the query |

Read it aloud: "Show each customer's name and the item, from customers joined to their orders, where the order total is over 20."
