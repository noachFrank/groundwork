## You already use this hundreds of times a day

Every time you open a web page, your computer has a short, fast conversation with computers around the world. Almost every technical problem a client will ever bring you lives somewhere in that conversation: "the site is down", "it's slow", "it works for me but not for them".

If you can picture the trip, you can work out **where** a problem is. That's most of the job.

Step through it. Don't rush, and read each step:

## The five stages

1. **Find the address.** Names are for people. Computers connect using numbers called **IP addresses**. **DNS** turns one into the other.
2. **Connect.** Your computer opens a connection to that address. For HTTPS, the two sides also set up encryption.
3. **Ask.** Your browser sends an **HTTP request**, a short text message saying what it wants.
4. **Work.** The server figures out the answer, often by asking a database.
5. **Answer.** The server sends an **HTTP response**: a status code like `200 OK`, plus the content. Your browser then displays it, and usually repeats the trip for each image, style and script.

The rest of this module takes those apart one at a time.

## What "localhost" means

In the task below you'll send requests to an address called `localhost`. That's a special name meaning **"this computer"**. Groundwork runs small practice servers on your own machine, so these are real requests using the real rules, and they need no internet.

<ConsultantNote>
"The website is down" can mean many different things. Is the name not resolving? Is the server refusing connections? Is it answering with an error? Knowing the stages turns a vague complaint into one precise question, and that's what clients pay for.
</ConsultantNote>
