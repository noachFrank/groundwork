## A very polite text conversation

**HTTP** (HyperText Transfer Protocol) is the language browsers and servers speak. A **protocol** is just an agreed set of rules for a conversation. Here's a real HTTP request, exactly as it travels:

```text
GET /orders/102 HTTP/1.1
Host: localhost:4314
Accept: application/json
```

- `GET` is the **method**: what you want to do. GET means "please send me…".
- `/orders/102` is the **path**: which thing you want. It's the part of a web address after the name and port.
- `HTTP/1.1` is the version of the rules being used.
- The lines after that are **headers**: extra information about the request, each one a name, a colon, and a value. `Host` says which site it's for. `Accept` says "I'd like JSON back, please".

And the response:

```text
HTTP/1.1 200 OK
Content-Type: application/json

{ "id": 102, "customer": "Grace", "item": "Monitor" }
```

- `200 OK` is the **status**: a number and a short phrase saying how it went.
- Then come the response's headers. `Content-Type` says what kind of content follows: here, JSON.
- Then a blank line, and the **body**: the actual content. For a web page, the body is HTML. For an API, it's usually JSON.

That's really all HTTP is: text in a fixed layout. Every page you've ever loaded was a conversation like this.

## Methods: what do you want to do?

| Method | Meaning | Example |
| --- | --- | --- |
| GET | Read something | See order 102 |
| POST | Create something, or send data | Place a new order |
| PUT | Replace or update something | Change an order |
| DELETE | Remove something | Cancel an order |

Typing an address in your browser always sends a GET. Submitting a form usually sends a POST.

## Status codes: how did it go?

The first digit tells you who to look at:

| Family | Meaning | Common examples |
| --- | --- | --- |
| **2xx** | It worked | `200 OK`, `201 Created` |
| **3xx** | Go somewhere else | `301 Moved Permanently`, `302 Found` |
| **4xx** | **Your request** has a problem | `400 Bad Request`, `401 Unauthorized` (not logged in), `403 Forbidden` (logged in, but not allowed), `404 Not Found`, `429 Too Many Requests` |
| **5xx** | **The server** has a problem | `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable` |

So a 4xx means look at what was sent: a wrong address, a missing login, bad data. A 5xx means look at the server: a crash, an overload, a broken connection to something behind it.

<details>
<summary>Quick check: a user gets 403 Forbidden on an admin page. Are they logged in?</summary>

Yes, probably. 401 means "not logged in". 403 means "we know who you are, but you're not allowed in here".
</details>

## Splitting a status line in Python

The Python task asks you to pull the number out of a status line like `"HTTP/1.1 404 Not Found"`. One new tool does most of the work: **`.split()`**, which breaks text into a list of words, wherever there are spaces:

```python
"HTTP/1.1 404 Not Found".split()
# ["HTTP/1.1", "404", "Not", "Found"]
#      0         1      2       3
```

From there it's what you already know: pick the item at position 1, and turn the text `"404"` into the number 404 with `int()`.

## HTTP has no memory

HTTP is **stateless**: each request stands completely alone, and the server doesn't remember the last one. So how do websites keep you logged in from one page to the next?

**Cookies.** When you log in, the server's response includes a header asking the browser to store a small piece of text, a cookie, often a long random code that identifies your login. The browser then sends that cookie back, in a header, with every request to the same site. The server sees it and knows it's you.

That's why logging out of one site, or clearing your cookies, logs you out: the browser stops sending the cookie.

<ConsultantNote>
A status code cuts through a confusing bug report fast. "The app is broken" could be a 401 (their login expired), a 404 (a wrong link), or a 503 (the server's down), and each is a completely different problem. Opening the browser's Network tab (F12) and reading the status code is often step one of a diagnosis.
</ConsultantNote>
