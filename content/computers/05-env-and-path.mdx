## Settings every program can see

An **environment variable** is a named piece of text that programs can read. Windows sets lots of them: your user name, where your home folder is, where temporary files go. In PowerShell you read one with `$env:` and its name:

```powershell
$env:USERNAME      # sam
$env:USERPROFILE   # C:\Users\sam
```

Every process gets its **own copy** of these settings, inherited from whatever started it. That detail explains a lot of confusing behavior.

## PATH: how commands are found

The most important environment variable is **PATH**. It's a list of folders separated by semicolons:

```text
C:\Windows\system32;C:\Windows;C:\Program Files\Git\cmd;...
```

When you type a command like `curl` or `node`, Windows looks in each of those folders, in order, for a matching program. It runs the first one it finds. If none of the folders has it:

```text
node : The term 'node' is not recognized as the name of a cmdlet, function, script file, or operable program.
```

That message almost never means the program is broken. It means **Windows couldn't find it**.

### Why a new terminal fixes things

Installers often add their folder to PATH. But a terminal copies the environment once, when it opens. A window that was already open still has the old PATH, so close it and open a new one. You just saw the reverse: your `$env:PATH` change vanished when you closed the window.

To change PATH permanently, use the Windows settings: search the Start menu for **"environment variables"**. The installer usually does this for you, if you let it.

## Keeping secrets out of code

Apps need passwords, database addresses and API keys. Writing them directly in the code is a classic mistake: code is shared, copied and kept in Git history forever, so anyone with the code gets the keys.

Instead, apps read them from environment variables:

```javascript
const apiKey = process.env.PAYMENT_API_KEY;
```

During development, these often live in a file called `.env`:

```text
PAYMENT_API_KEY=sk_test_abc123
DATABASE_URL=postgres://localhost/shop
```

<Callout kind="warn" title="The .env rule">
A `.env` file must **never** be committed to Git or shared. You'll see how to make Git ignore it in the Git module. Leaked keys get found and abused by automated bots within minutes.
</Callout>

<ConsultantNote>
When you review a client's code, search it for passwords and keys. Finding them written into the code, or a committed `.env` file, is one of the most common and serious problems in small companies' software, and one of the easiest to fix.
</ConsultantNote>
