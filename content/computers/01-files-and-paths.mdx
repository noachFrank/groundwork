## Everything is a file in a folder

Your photos, your documents, and every program on your computer, including Groundwork, are **files**. Files live in **folders**, also called **directories**, and folders can hold other folders. Together they make a tree.

At the top of the tree on Windows is a **drive**, usually `C:`. Your own files live in your **home folder**, `C:\Users\your-name`.

## Paths are addresses

A **path** writes down exactly where a file is, one folder at a time:

```text
C:\Users\sam\Documents\cv.docx
│  │     │   │         └── the file
│  │     │   └── a folder inside sam
│  │     └── sam's home folder
│  └── the Users folder
└── the C drive
```

On Windows, folders are separated by a **backslash** `\`. On Mac, Linux and in web addresses, they use a **forward slash** `/`. You'll see both constantly.

### Absolute and relative

- An **absolute** path starts at the drive, `C:\...`. It works from anywhere.
- A **relative** path starts from wherever you are right now. If you're in `C:\Users\sam`, then `Documents\cv.docx` points to the same file.

Two shortcuts appear in relative paths all the time:

| | Means |
| --- | --- |
| `.` | The folder I'm in |
| `..` | The folder above this one |
| `$HOME` or `~` | My home folder |

## File extensions

The letters after the last dot in a file name, like `.docx`, `.txt` or `.exe`, are the **extension**. They tell Windows what kind of file it is and which program opens it.

Windows hides extensions by default, which is unhelpful. Turn them on: open File Explorer, click **View** → **Show** → **File name extensions**. You'll need to see them for the rest of this course.

<Callout kind="warn" title="Hidden extensions hide tricks">
A file called `invoice.pdf.exe` shows up as `invoice.pdf` when extensions are hidden. It looks like a document, but it's a program. Seeing extensions helps you spot that.
</Callout>

## The terminal is another view of the same files

File Explorer and the terminal show the same files. The terminal just uses typing instead of clicking. Developers use it because it's faster for many jobs, it can be repeated exactly, and instructions for software are almost always written as terminal commands.

At any moment, the terminal is "in" one folder, called the **current directory**. Commands work relative to it.

<ConsultantNote>
"I can't find the file" and "it says the file doesn't exist" are some of the most common problems you'll help people with. Nine times out of ten, the program is looking in a different folder than they think. Asking "what's the full path?" solves a lot.
</ConsultantNote>
