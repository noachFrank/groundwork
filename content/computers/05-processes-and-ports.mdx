## In this lesson

- The difference between a **program** and a **process**.
- What a **server program** is, and what it means for one to **listen on a port**.
- What `localhost` means, and what it has to do with the address you use to open Groundwork.
- How to find out which program is using a port, and how to stop it.

You'll use Groundwork itself as the example, because it's a server program running on your computer right now.

## A program is a recipe. A process is the cooking.

A **program** is a file on disk, like `node.exe` or `chrome.exe`. It just sits there, like a recipe in a book.

When you run it, the computer loads the program into its working memory and starts following its instructions. That running copy is called a **process**. It's the cooking, happening right now.

- One program can run as many processes at the same time. Chrome often runs dozens, one for each tab and more.
- Each process gets an ID number, its **PID** (process ID), so the computer and you can tell them apart.
- Each process uses some memory and some processor time while it runs.
- When a process ends, whatever it was doing stops. The program file is still on disk, ready to run again.

To see your processes, open **Task Manager** with **Ctrl+Shift+Esc**. The list on the first tab is your running processes. In PowerShell, `Get-Process` shows the same list as text.

<details>
<summary>Quick check: you have Chrome open with three tabs. How many programs is that? How many processes?</summary>

One program, Chrome. But many processes, at least one per tab, plus a few more that Chrome uses behind the scenes.
</details>

## Browsers, requests and responses

Now for how websites work, at the simplest level. You'll come back to this in much more depth in Stage 2.

A **browser** is the program you use to view websites: Chrome, Edge, Firefox or Safari. When you type a web address and press Enter, the browser sends a message asking for that page. That message is a **request**. Some program, somewhere, receives the request and sends back the page. Its reply is called a **response**.

```text
Browser ──── request: "send me the home page" ────▶ server program
Browser ◀─── response: the page ─────────────────── server program
```

The program that answers is a **server program**, or just a **server**. In the Bash lesson, "server" meant a computer that provides something to others. People use the same word for the program doing the providing. Usually it's obvious which one is meant.

## Servers are processes that wait

Most programs do something and then finish. A server program is different: it starts, then **waits**, sometimes for weeks, ready to answer requests whenever they arrive. Waiting like this is called **listening**.

That's exactly what the black Groundwork window is. When you started Groundwork, a Node process began running Groundwork's server code. It's been listening ever since. Every time you click something in Groundwork, your browser sends it a request and it sends back a response.

So when you close the black window, the process ends, nothing is listening any more, and the browser's requests go unanswered. Pages already on screen stay there, but nothing new works.

## Ports: which program gets the message?

One computer can run many server programs at once. When a request arrives, how does the computer know which program it's for? With a **port**.

A port is a number, from 1 to 65535, that a server program claims when it starts listening. Think of the computer as an apartment building and ports as apartment numbers: the building's address gets the request to the right computer, and the port number gets it to the right program inside.

Groundwork's server listens on port **4310**. Look at your browser's address bar while using Groundwork:

```text
http://localhost:4310/lessons/processes-and-ports
                 ^^^^ the port
```

Some ports have traditional uses. Ordinary websites use port 80, or 443 for secure ones, and browsers fill those in for you, which is why you rarely see a port number in a normal web address.

## localhost: this computer

The other part of that address, `localhost`, is a special name that always means **this computer, the one you're using**. A request to localhost never leaves your machine.

Behind the name, every computer on a network has a numeric address, called an IP address. You'll learn about them properly in Stage 2. The one you need now is `127.0.0.1`, which is the numeric address that `localhost` stands for. Both mean "this computer".

So `http://localhost:4310` means "ask the program listening on port 4310, on this computer".

<details>
<summary>Quick check: what do the two parts of `localhost:4310` mean?</summary>

`localhost` means this computer. `4310` is the port, which picks out which program on this computer should receive the request: Groundwork's server.
</details>

## "Port already in use"

Only one process can listen on a given port at a time. If a second program tries to claim a port that's taken, it fails with an error like:

```text
Error: listen EADDRINUSE: address already in use :::3000
```

Read it like any error: `listen` (it was trying to start listening), `EADDRINUSE` (a short code for "address in use"), and `3000` (the port it wanted).

The usual cause is an old copy of the same server still running, perhaps in a terminal window you forgot about. The fix:

1. Find out which process owns the port: `Get-NetTCPConnection -LocalPort 3000`. The **OwningProcess** column is its PID.
2. Look at that process: `Get-Process -Id 24688` (using the PID you found).
3. If it's safe to stop, stop it: `Stop-Process -Id 24688`, or close its window, or press **Ctrl+C** in the terminal it's running in.

You'll run steps 1 and 2 on Groundwork's own port in the task.

## Who can connect?

When a server starts listening, it also says which address it's listening on. That decides who can reach it:

| Listens on | Who can connect |
| --- | --- |
| `127.0.0.1` (localhost) | Only programs on this same computer. Groundwork does this, so nobody else on your Wi-Fi can open it. |
| `0.0.0.0` | Any computer that can reach this one over the network. That's why Windows Firewall sometimes pops up asking for permission. |

## Stopping processes

| Way | When |
| --- | --- |
| **Ctrl+C** in its terminal | It's running in a terminal window you can see |
| Close its window | Same, but less gentle |
| `Stop-Process -Id <PID>` or `-Name <name>` | You know its ID or name |
| Task Manager → select it → **End task** | You prefer clicking |

Stopping a process you don't recognize can make other things misbehave. If you're not sure what it is, look it up first.

<ConsultantNote>
"The site is down" sometimes just means the server process crashed and nothing restarted it. Real servers use a **process manager**, or a hosting service, that restarts crashed processes automatically. "What restarts it if it dies?" is a good question to ask about any client system.
</ConsultantNote>
