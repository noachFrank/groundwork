## A program is a recipe. A process is the cooking.

A **program** is a file on disk, like `node.exe` or `chrome.exe`. When you run it, the computer loads it into memory and starts following its instructions. That running copy is a **process**.

- One program can run as many processes. Chrome runs dozens.
- Each process has an ID number, its **PID**.
- Each uses some memory and processor time while it runs.
- When a process ends, whatever it was doing stops.

Task Manager (**Ctrl+Shift+Esc**) shows them all. So does `Get-Process` in PowerShell.

## Servers are processes that wait

Most programs do something and finish. A **server** is different: it starts, then waits, often for weeks, listening on a **port** for requests.

That's what the black Groundwork window is. It's a Node.js process listening on port 4310. Your browser sends requests to `localhost:4310`, and that process answers. Close the window and the process ends, so the browser's requests go unanswered.

```text
Browser ──request──▶ localhost:4310 ──▶ node (process 24688) ──▶ answer
```

## "Port already in use"

Only one process can listen on a given port at a time. If a second program tries, it fails with an error like:

```text
Error: listen EADDRINUSE: address already in use :::3000
```

The usual cause is an old copy of the same server still running, perhaps in a terminal window you forgot about. The fix:

1. Find out what owns the port: `Get-NetTCPConnection -LocalPort 3000`.
2. Look at the process: `Get-Process -Id <OwningProcess>`.
3. If it's safe to stop, stop it: `Stop-Process -Id <OwningProcess>`, or close its window.

## Who can connect?

The address a server listens on decides who can reach it:

| Listens on | Who can connect |
| --- | --- |
| `127.0.0.1` (localhost) | Only this computer. Groundwork does this. |
| `0.0.0.0` | Any computer that can reach this one, which is why Windows Firewall asks for permission |

<ConsultantNote>
"The site is down" sometimes just means the server process crashed and nothing restarted it. Real servers use a **process manager** or a hosting platform that restarts crashed processes automatically. "What restarts it if it dies?" is a good question to ask about any client system.
</ConsultantNote>
