## Why Bash matters even on Windows

Most of the servers that run websites and apps use **Linux**, and Linux is controlled through a shell called **Bash**. Macs use a very similar shell called zsh. So documentation, tutorials and AI answers are full of Bash commands, and sooner or later a client will ask you to look at a Linux server.

You don't need to master it now. You need to **recognize** the common commands and know where the dangers are.

## PowerShell and Bash side by side

| Job | PowerShell | Bash |
| --- | --- | --- |
| Where am I? | `Get-Location` (`pwd`) | `pwd` |
| List files | `Get-ChildItem` (`ls`) | `ls` (`ls -la` for details and hidden files) |
| Change folder | `cd folder` | `cd folder` |
| Show a file | `Get-Content file` | `cat file` |
| Make a folder | `mkdir name` | `mkdir name` |
| Copy | `Copy-Item a b` | `cp a b` |
| Move or rename | `Move-Item a b` | `mv a b` |
| Delete | `Remove-Item file` | `rm file` |
| Watch a log live | `Get-Content log -Wait` | `tail -f log` |

## What's different on Linux

- **Forward slashes**, and no drive letters. Everything starts from `/`, called the root. Your home folder is `~`.
- **Case matters.** `Logo.png` and `logo.png` are different files.
- **Hidden files** start with a dot, like `.env` or `.git`.
- **Scripts** end in `.sh`, start with a line like `#!/bin/bash`, and must be marked as runnable with `chmod +x script.sh` before you run them with `./script.sh`.
- **sudo** runs a command as the administrator, called root. It's sometimes necessary, and always worth a second look.

<Callout kind="warn" title="No undo">
`rm` deletes immediately. There's no Recycle Bin. `rm -rf` deletes a folder and everything in it without asking. Read any delete command twice, and be especially wary of `*`, which means "everything here".
</Callout>

## Where you'll use Bash

- **Logging in to a server** with `ssh user@server`, which gives you a Bash prompt on that machine.
- **Git Bash**, which comes with Git for Windows, the Git and GitHub module's tool. It gives you Bash on your own laptop.
- **Automated builds and deployments.** Services like GitHub Actions run Bash scripts to test and publish code.

<ConsultantNote>
When you audit a client's setup, deploy scripts are worth reading. Scripts that keep going after an error, delete with `*`, or run everything with sudo are common, and they're exactly the kind of risk a client won't know they have until something breaks.
</ConsultantNote>
