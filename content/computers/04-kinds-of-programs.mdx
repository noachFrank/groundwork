## In this lesson

- What a **programming language** is, and why there are so many.
- How the code people write becomes something a computer can actually run.
- What **Python**, **JavaScript** and **Node.js** are. You'll see these names in nearly every lesson from here on.
- Which kinds of files run on their own, and which need another program to run them.

## Code is text. Computers need numbers.

In the first lesson of the course you saw that **code** is instructions for a computer, written as text. Here's the catch: a computer's processor, the chip that does the actual work, can't read text at all. It only understands **machine code**: long strings of numbers, each one a tiny instruction like "add these two numbers" or "copy this value over there".

Writing machine code by hand would be unbearably slow, and almost nobody does it. Instead, people write code in a **programming language**: a set of words and punctuation rules designed to be readable by humans *and* precise enough for a computer. The text people write is called **source code**.

Then some program has to turn that source code into machine code. There are two main ways it happens.

## Two ways to run code

### Compiled

A tool called a **compiler** reads the whole program once, ahead of time, and translates it into machine code. The result is a new file, like `app.exe`, that the computer can run directly.

It's like translating a whole book into another language before publishing it. Readers get a translated book and never see the original.

- **Good:** fast to run, and the person running it doesn't need any extra software.
- **Bad:** after every change to the source code, you have to compile again.

Languages usually compiled this way include C, C++, Go, Rust and C#.

### Interpreted

The source code stays as a text file, a **script**. Each time you want to run it, a program called an **interpreter** reads the script and carries out its instructions as it goes.

It's like having a live interpreter at a meeting, translating each sentence as it's spoken. The original is still there, and changes take effect immediately.

- **Good:** change the script, run it again, and you see the change straight away.
- **Bad:** whoever runs it needs the interpreter installed.

**Python** and **JavaScript** are usually run this way.

Real life is blurrier than this. Some interpreters secretly compile parts of the code while it runs, to make it faster. But the practical question is always the same: **can this file run by itself, or does it need another program?**

## The languages you'll meet in this course

There are hundreds of programming languages. You'll mostly use two.

**Python** is known for being easy to read. It's used for automating boring jobs, working with data, science, and AI. A line of Python:

```python
print("Hello")
```

**JavaScript** is the language of the web. Every web browser, like Chrome or Edge, has a JavaScript interpreter built in. That's how websites become interactive: when you click a button and something changes without the page reloading, that's usually JavaScript running in your browser. A line of JavaScript:

```javascript
console.log("Hello");
```

`console.log(...)` is JavaScript's way of printing something. You'll see it in this lesson's task.

You'll learn to read and write both properly in the *Reading code* module. For now, just recognize their names and their file extensions: `.py` for Python, `.js` for JavaScript.

## Node.js: JavaScript outside the browser

For years, JavaScript could **only** run inside web browsers. Then **Node.js**, usually just called **Node**, came along. Node is a JavaScript interpreter that runs on its own, outside any browser. You give it a `.js` file, and it runs it:

```text
node hello.js
```

That made JavaScript useful for things that have nothing to do with web pages, like scripts, tools, and **servers**, the always-on programs you met in the Bash lesson.

**Groundwork itself is written in JavaScript and run by Node.** The black window you keep open while you study is Node, running Groundwork's code. And Groundwork brought its own copy of Node with it, in a folder inside the app, which is what you'll use in the task.

<details>
<summary>Quick check: what's the difference between JavaScript and Node.js?</summary>

JavaScript is a programming language. Node.js is a program, an interpreter, that runs JavaScript outside a web browser.
</details>

## Running a program by its path

Normally, to run a program from the terminal, you type its name, like `node`. That only works if Windows knows where to find it. How Windows searches for programs is the topic of the lesson after next. Until then, you can always run a program by giving its **full path**:

```powershell
& "C:\Groundwork\.runtime\node\node.exe" hello.js
```

- The path is in quotes, in case it has spaces.
- `&`, the **call operator**, tells PowerShell "run the program at this path", rather than treating the quoted text as just some text.
- `hello.js` after it is an argument: the script for Node to run.

In the task, the Copy button fills in the real path to Groundwork's Node for you.

## The file types you'll meet

| Extension | What it is | What runs it |
| --- | --- | --- |
| `.exe` | A compiled Windows program | Windows itself |
| `.bat`, `.cmd` | A **batch file**: a list of commands for cmd, the older Windows shell | Windows (cmd) |
| `.ps1` | A PowerShell script | PowerShell, if allowed |
| `.sh` | A Bash script | Bash, on Linux or Mac |
| `.py` | A Python script | The Python interpreter |
| `.js` | A JavaScript script | Node.js, or a browser |

`start.bat`, the file you double-clicked to start Groundwork, is a batch file. It checks a few things, then asks Node to run Groundwork's JavaScript. In the task you'll make a tiny batch file that does the same thing with your own script.

## Why .ps1 files are blocked

By default, Windows won't run PowerShell script files (`.ps1`). Try, and you get an error mentioning "running scripts is disabled on this system". That setting is called the **execution policy**, and it exists to stop people being tricked into running harmful scripts.

You'll meet one practical effect of this soon. Some tools, like **npm** (a tool that comes with Node, covered in the *Packages* lesson), install two versions of their command: a `.ps1` one and a `.cmd` one. In PowerShell, typing `npm` can pick the `.ps1` version and hit the block. Typing `npm.cmd` picks the batch version, which isn't blocked. That's why later lessons say `npm.cmd`.

<Callout kind="warn" title="'Windows protected your PC'">
That blue box is Windows **SmartScreen**. It appears for programs downloaded from the internet that Windows doesn't recognize. It's right to make you stop and think. Click **Run anyway** only when you know exactly where the file came from.
</Callout>

<ConsultantNote>
"What language is it written in, and what does it need to run?" is one of the first questions to ask about any client system. A Python app needs Python on the server, in the right version. A compiled app might need a particular version of Windows. Missing pieces like these cause many failed launches.
</ConsultantNote>
