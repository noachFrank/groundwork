## It's just a shortcut

Every JavaScript project has a `package.json`, and most have a `scripts` section like this:

```json
"scripts": {
  "dev": "vite",
  "build": "vite build",
  "test": "vitest"
}
```

`npm run dev` simply means: **look up "dev" and run that command**. The names are conventions, not magic. If a README says `npm run dev` and you get "Missing script", open package.json and see which scripts actually exist.

npm also does one helpful thing: it lets the command use programs from the project's own packages. That's how `vite` runs even though you never installed it on its own.

## The usual routine

```text
npm install      ← once, to download the packages into node_modules
npm run dev      ← every time you want to work on it
```

Downloading a project's code doesn't download its packages, because `node_modules` isn't stored in Git. So "packages missing" errors after downloading usually mean you skipped `npm install`.

## What a dev server does

Most `dev` scripts start a **development server**: a process that serves the app at an address like `http://localhost:5173`. While it runs, it:

- Watches the project's files.
- Rebuilds and refreshes the browser the moment you save a change, called **hot reload**.
- Shows helpful, detailed error messages.

It's a process like any other. It lives in that terminal window, so **closing the terminal stops it**. That's the same reason you keep the black Groundwork window open.

## Dev and build

The dev server is for working on code. To publish a site, you run a **build**:

| | `npm run dev` | `npm run build` |
| --- | --- | --- |
| Purpose | Working on the code | Making files to publish |
| Output | A running server on localhost | A folder, often `dist`, of optimized files |
| Speed of changes | Instant reload | Run again after every change |
| Error messages | Detailed, for developers | Hidden from visitors |

Groundwork works the same way. On its first start, `start.bat` ran a build into `dist`, then started a small server that serves it.

<Callout title="Two kinds of 'server' in one project">
Many projects have both a dev server for the frontend, like Vite on port 5173, and a backend server, like an API on port 3000. Groundwork has the same thing: when developers work on it, `npm run dev` starts both.
</Callout>
