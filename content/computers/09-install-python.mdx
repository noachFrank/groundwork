## Installing things is part of the job

So far, Groundwork has run Python for you, inside the app. Real projects need Python installed on the computer. Installing tools, and fixing installs that went wrong, is a skill you'll use constantly, for yourself and for clients.

## The two traps

Almost every "Python doesn't work" problem on Windows is one of these.

### 1. The PATH box

The python.org installer has a checkbox at the bottom of its first screen: **Add python.exe to PATH**. It's **not ticked** by default. Without it, Python is installed, but typing `python` gives "not recognized", because Windows doesn't know which folder to look in. You learned exactly why in the PATH lesson.

### 2. The Microsoft Store alias

Windows comes with a fake `python` command that just opens the Microsoft Store. If the real Python isn't on PATH, or comes later in PATH, you get the Store instead. You can switch these off in **Settings → Apps → Advanced app settings → App execution aliases**.

Python on Windows also installs `py`, a launcher that finds whichever Python versions you have. `py --version` is a good fallback.

## Virtual environments

Imagine two projects: one needs version 1 of a package, and one needs version 2. If packages were installed for the whole computer, they'd fight. A **virtual environment** solves this: a folder, usually called `.venv`, with its own private set of packages.

```powershell
python -m venv .venv                          # make it
.\.venv\Scripts\python.exe -m pip install X   # install into it
```

You'll often see instructions say to **activate** it first, with `.venv\Scripts\Activate.ps1`. That's a PowerShell script, so the execution policy may block it. Running `.venv\Scripts\python.exe` directly does the same job without activating.

| Python | JavaScript |
| --- | --- |
| `pip` | `npm` |
| `.venv` folder | `node_modules` folder |
| `requirements.txt` | `package.json` and its lockfile |

As with node_modules, `.venv` is never committed to Git. The `requirements.txt` file is.

<ConsultantNote>
Clear setup instructions are a gift. When you hand a project to a client, include exactly which version of Python or Node to install, which boxes to tick, and the commands to run, in order. Most "it doesn't work" calls after a handover come from a missing setup step.
</ConsultantNote>
