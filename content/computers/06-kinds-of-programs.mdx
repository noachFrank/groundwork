## Two ways to run code

Computers' processors only understand **machine code**: long strings of numbers. Nobody writes that by hand. People write code in languages like C#, Python or JavaScript, and it gets turned into something the machine can run in one of two ways.

**Compiled.** A tool called a compiler translates the whole program into machine code ahead of time, producing a file like `app.exe`. You can then run it directly. It's fast, but you have to recompile after every change.

**Interpreted.** The code stays as text, a **script**, and a program called an **interpreter** reads and runs it each time. Python and Node.js are interpreters. Change the script, and the next run uses the change.

Real life is blurrier. Many languages, including JavaScript in Node, are compiled on the fly while they run. But the practical question is always the same: **can this file run by itself, or does it need another program?**

## The file types you'll meet

| Extension | What it is | What runs it |
| --- | --- | --- |
| `.exe` | A compiled Windows program | Windows itself |
| `.bat`, `.cmd` | A list of commands for cmd | Windows (cmd) |
| `.ps1` | A PowerShell script | PowerShell, if allowed |
| `.sh` | A Bash script | Bash, on Linux or Mac |
| `.py` | A Python script | Python |
| `.js` | A JavaScript script | Node.js, or a browser |

`start.bat`, which starts Groundwork, is exactly this pattern: a batch file that sets things up, then asks Node to run Groundwork's JavaScript.

## Why .ps1 files are blocked

By default, Windows won't run PowerShell scripts you double-click or type the name of. You'll see an error mentioning "running scripts is disabled on this system". That setting is called the **execution policy**, and it exists to stop people being tricked into running harmful scripts.

That's also why commands in this course sometimes say `npm.cmd` instead of `npm`. The `npm` command has a `.ps1` version that the policy can block, and a `.cmd` version that it doesn't.

<Callout kind="warn" title="'Windows protected your PC'">
That blue box is Windows SmartScreen. It appears for programs downloaded from the internet that Windows doesn't recognize. It's right to make you stop and think. Click **Run anyway** only when you know exactly where the file came from.
</Callout>

"What language is it written in, and what does it need to run?" is one of the first questions about any client system. A Python app needs Python on the server, in the right version. A compiled app might need a specific Windows or .NET version. Missing pieces like these cause many failed deployments.
</ConsultantNote>
